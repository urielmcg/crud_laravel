2. Estructura .env (solo lo que cambiamos)

Tu conexión original (almacenjuvenil/controlador/conexion.php:5-8): host=localhost, db=juvenil, user=root, pass="". Se replica en crudlaravel/.env:

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=juvenil
DB_USERNAME=root
DB_PASSWORD=

SESSION_DRIVER=file      # antes: database (evita necesitar tabla sessions en MySQL)
CACHE_STORE=file         # antes: database
QUEUE_CONNECTION=sync    # antes: database

Qué hace cada una: DB_* = a qué base se conecta Eloquent. SESSION_DRIVER=file guarda sesiones en storage/framework/sessions en vez de la BD. CACHE_STORE=file y QUEUE_CONNECTION=sync evitan necesitar las tablas cache/jobs para este CRUD simple.

3. Base de datos juvenil.sql + migración

Dump: 12 tablas (usuarios, administrador, cliente, cargo, empleado, proveedor, producto, compra, detalle_compra, venta, detalle_venta, clienteantiguo). La central es:

usuarios(id_usuario AI PK, nombreusuario 35, password 35, tipousuario,
         estado, nombre, paterno, materno, fecha, ci, email)
FKs que apuntan a ella: administrador.usuario_id, cliente.usuario_id
Hallazgo crítico: password VARCHAR(35) no alcanza para bcrypt (60 caracteres). Por eso se creó migración que solo amplía la columna, sin borrar tus 11 usuarios reales.

Archivo: database/migrations/2026_10_04_000001_ajustar_password_usuarios_table.php

// up() con php artisan migrate | down() con migrate:rollback
if (Schema::hasTable('usuarios')) {
    Schema::table('usuarios', function (Blueprint $table) {
        $table->string('password', 255)->change(); // 35 → 255
    });
}

Ejecutado y verificado: php artisan migrate --force → DONE, DESCRIBE juvenil.usuarios muestra password varchar(255). Nota: la BD viva tiene columna extra id_empleado que no está en el .sql; el CRUD la ignora (queda NULL).

4. Modelo app/Models/Usuario.php

class Usuario extends Model
{
    protected $table = 'usuarios';   // tabla real (no la 'users' de Laravel)
    protected $primaryKey = 'id_usuario'; // tu PK no se llama 'id'
    public $incrementing = true;     // autoincremental
    protected $keyType = 'int';
    public $timestamps = false;      // tu tabla NO tiene created_at/updated_at
    protected $fillable = [          // lista blanca para create()/update()
        'nombreusuario','password','tipousuario','estado',
        'nombre','paterno','materno','fecha','ci','email',
    ];
    protected $hidden = ['password']; // no exponer hash en JSON
}

Por qué cada línea: sin $primaryKey el Route Model Binding buscaría id y fallaría. Sin $timestamps=false daría unknown column created_at. Sin $fillable daría MassAssignmentException.

7. STORE + validaciones

$datos = $request->validate([
  'nombreusuario' => 'required|string|max:35|unique:usuarios,nombreusuario',
  'password' => ['required','string','min:8','regex:/[A-Z]/','regex:/[!@#$%^&*(),.?":{}|<>]/'],
  'tipousuario' => 'required|in:administrador,cliente',
  'estado' => 'required|in:activo,inactivo',
  'nombre' => 'required|string|max:35', 'paterno' => 'required|string|max:35',
  'materno' => 'nullable|string|max:35', 'fecha' => 'nullable|date',
  'ci' => 'nullable|string|max:20', 'email' => 'nullable|email|max:100',
]);
$datos['password'] = Hash::make($datos['password']); // bcrypt, reemplaza password_hash()
Usuario::create($datos); // usa $fillable
return redirect()->route('usuarios.index')->with('ok','Usuario creado correctamente.');

La regla de password replica tu validarPasswordServer() (min 8 + mayúscula + símbolo). Si falla, Laravel redirige atrás con errores automáticamente.

10. DELETE: destroy() y error FK 1451

Error que viste: SQLSTATE 1451 ... cliente_ibfk_1 ... delete from usuarios where id_usuario=6. El usuario 6 (saulos) tiene hijo cliente id 4 (Centro de Idiomas); MySQL impide borrar al padre.

try {
    DB::transaction(function () use ($usuario) {
        DB::table('cliente')->where('usuario_id',$usuario->id_usuario)->delete();
        DB::table('administrador')->where('usuario_id',$usuario->id_usuario)->delete();
        $usuario->delete(); // recién ahora el padre
    });
    return redirect()->route('usuarios.index')->with('ok','Usuario eliminado correctamente.');
} catch (QueryException $e) {
    return redirect()->route('usuarios.index')
        ->withErrors('No se puede eliminar: tiene registros relacionados. Desactívalo con estado=inactivo.');
}

Replica tu lógica usuarioControlador.php:166-185 + eliminarConHerencia(). Verificado creando y borrando un usuario temporal con cliente (borrado OK). Para borrado lógico usa $usuario->update(['estado'=>'inactivo']) como tu desactivar().
